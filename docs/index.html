Protocol & Connectivity

How Agents Connect

Inter-agent communication relies on clean webhooks, event-driven Discord WebSocket messaging, and automated Git version control pipelines.

1. n8n Node-to-Node Bus

The primary workflow engine acts as the central nerve center. Webhooks and Sub-workflow nodes route JSON payloads across specialized agent nodes.

  • Structured JSON Payload Transfer
  • Parallel Task Fan-Out Execution
  • Exception Handling & Retry Retries

2. Discord Bot-to-Bot Gateway Protocol

`n8n-bot` posts spec files to Discord tagging `@hermes-bot`. The Hermes daemon listens to the WebSocket gateway stream and triggers processing instantly.

  • Decoupled Async Message Queue
  • File Attachment & Context Passing
  • Transparent Discord Audit Trail

3. Autonomous Sandbox Execution

Hermes Agent processes the specification inside an isolated Virtual Machine (Linux Mint / UTM), executing shell scripts, creating HTML/JS, and testing logic.

  • Isolated Linux VM Execution
  • Automated Code Refactoring
  • GitHub CLI (`gh`) Authentication

4. GitHub Pages Deployment

Once code generation is complete, Hermes executes `git push origin main` into target repositories, triggering GitHub Pages live deployment automatically.

  • Automated CI/CD Web Hosting
  • Live Production URL Mapping
  • Version-Controlled Commit History

Governance & Trust

Responsible AI & Guardrails

Deploying AI at enterprise scale requires embedded security, auditability, data privacy, and mandatory human oversight.

1. VM Execution Sandboxing

Autonomous shell execution runs strictly inside guest Linux VMs (VirtualBox / UTM). The host environment and primary network remain completely protected.

  • Hypervisor Hardware Boundary
  • Read-Only Shared Mount Protection
  • Clean Ephemeral OS Sessions

2. Zero-Trust Secrets Defense

API tokens and credentials live inside n8n encrypted vaults and environment files (`.env`). Hardcoding credentials into code or Git is blocked.

  • Minimal OAuth 2.0 Scopes
  • Automated Git Secret Scanning
  • Encrypted Environment Store

3. Human-in-the-Loop (HITL) Validation

Key milestones (such as emailing public stakeholders or deploying code) require explicit human sign-off from domain leaders.

  • n8n Interactive Approval Nodes
  • Discord Reaction Approval Hooks
  • Complete Timestamp Audit Trail

4. Model Fallbacks & Safety Chains

Multi-provider fallbacks (`openrouter/auto`, local Ollama) ensure the ecosystem operates without interruption or single-point dependency failures.

  • Automatic Provider Failover
  • Strict JSON Schema Validation
  • Graceful Failure Recovery
